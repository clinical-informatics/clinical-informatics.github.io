## Go deeper: Project organization

**If you want one short reference that covers this whole track:**

- [Noble, "A Quick Guide to Organizing Computational Biology Projects" (PLoS Computational Biology 2009)](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1000424) is the canonical short paper on folder structure for a data project. The directory layout it proposes (separate `data`, `src`, `results`, `doc`) is the one most reproducible-research guidance still cites, and the article is open access and readable in fifteen minutes.

**If you want the broader set of practices:**

- [Wilson et al., "Good enough practices in scientific computing" (PLoS Computational Biology 2017)](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1005510) is the deliberately non-perfectionist companion: the practices a working researcher can actually adopt, across data management, project organization, version control, and collaboration. The "good enough" framing is the point, because perfect reproducibility infrastructure that no one maintains is worse than a modest setup that holds.

**If you want to go significantly further:**

- [The Turing Way, "Reproducible Research"](https://book.the-turing-way.org/reproducible-research/reproducible-research.html) develops project organization into the idea of a research compendium: a single self-contained bundle of data, code, and documentation that an independent group can pick up and rerun. The handbook's chapters on file structure and research data management extend this track's material in depth.
