## Go deeper

**If you want to understand FHIR search and the request/response cycle more deeply before moving on:**
- MITRE's "Using the FHIR API to Access Data" module pairs a clinical-research framing with concrete curl/Postman examples; it's the gentlest free introduction to the request/parse loop in book-chapter form. Pair it with the HL7 R4 RESTful API and Search pages, which are the canonical reference for every search parameter, every modifier (`:exact`, `:contains`, `:missing`), every chained search, and every result parameter (`_include`, `_revinclude`, `_summary`). You don't read the HL7 pages end to end; you bookmark them and return when a specific question comes up. [mitre.github.io/fhir-for-research/modules/fhir-accessing-data](https://mitre.github.io/fhir-for-research/modules/fhir-accessing-data), [hl7.org/fhir/R4/http.html](https://www.hl7.org/fhir/R4/http.html), and [hl7.org/fhir/R4/search.html](https://www.hl7.org/fhir/R4/search.html).

**If you want to see this applied to a real clinical research workflow:**
- Mandl KD, Mandel JC, Kohane IS. "Driving Innovation in Health Systems through an Apps-Based Information Economy" (Cell Systems, 2015). The paper introducing SMART on FHIR as a research and clinical-app substrate, written in plain enough English that you can read it without an informatics background. The architectural moves the paper describes (the substitutable app, the OAuth context, the FHIR data layer underneath) are what you'll meet in Track 5. The earlier "Time for a Patient-Driven Health Information Economy?" (NEJM, 2016) is paywalled but the abstract carries the core argument. [doi.org/10.1016/j.cels.2015.05.001](https://doi.org/10.1016/j.cels.2015.05.001)

**If you want to go significantly further:**
- The HAPI FHIR documentation. HAPI is the open-source reference FHIR server (it powers `hapi.fhir.org`). The "Server" section walks how a server actually handles a request: URL parsing, parameter resolution, paging, `_include` resolution, and the validate-and-store path for writes. Even if you never run HAPI yourself, reading the docs is the cleanest free explanation of what a FHIR server does on the inside. [hapifhir.io/hapi-fhir/docs/](https://hapifhir.io/hapi-fhir/docs/). For Python specifically, the `fhirpy` library is a worked example of an idiomatic FHIR client on top of the same RESTful API you've been calling directly. [pypi.org/project/fhirpy/](https://pypi.org/project/fhirpy/) and [github.com/beda-software/fhir-py](https://github.com/beda-software/fhir-py).
