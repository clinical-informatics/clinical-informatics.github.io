# Track 0: Before FHIR (no code)

> Ms. Reyes has one record in real life. She has two in this curriculum: one Epic-shaped, one Cerner-shaped. Same patient, same morning, same lab values. The two exports look almost nothing alike. Why?

This track builds the intuitions FHIR rests on (data shapes, the web, and a short history of healthcare data exchange) before introducing any FHIR resource names. It closes by walking four real differences between Ms. Reyes's two synthetic EHR exports and naming the interoperability layer each one lives at.

After this track, when a colleague says "the two systems can't talk," you can name which of the five interoperability layers (transport, format, structure, terminology, content) the problem is at. That specificity is the move that unblocks most interop conversations.


**How to start:** open `notebook.py` in this folder from the file tree on the left. Marimo loads it in app mode. There's no code to read. Every interaction is a radio, a multiselect, or a short reflection.

**Companion reading:** [`00.1-before-fhir.md`](00.1-before-fhir.md) is a short reference essay covering the same four foundational ideas. Read it first, after, or skip it. It's not a prerequisite.

**What's next:** Track 1 introduces FHIR resources, references, and bundles. The vocabulary moves quickly; the structure underneath it is what this track put in place.
